# QQ炫舞 3.0

3.0 以 `正式版1.9.py` 的 17 张地图为兼容基线，并新增“蘑菇半图上层备用”、独立重构的“蘑菇V2”和录制路线驱动的“蘑菇V3”，当前共 20 个地图选项。旧版文件没有被覆盖，新的启动入口是 `正式版3.0.py`。

## 启动

双击 `启动3.0.bat`，或在项目目录执行：

```powershell
python .\正式版3.0.py
```

本机默认的 `python` 是 32 位 Python 3.8，无法运行当前 PyTorch。启动脚本会优先使用已经具备完整依赖的 64 位 Python 3.12：

```powershell
& "$env:LocalAppData\Programs\Python\Python312\python.exe" .\正式版3.0.py
```

如果环境缺少依赖：

```powershell
python -m venv .\.venv
.\.venv\Scripts\python.exe -m pip install -r .\requirements-3.0.txt
```

本项目已验证的 Windows CPU 推理组合为 PyTorch `2.5.1` 与 torchvision
`0.20.1`。安装完成后，IDE 的项目解释器应选择：

```text
D:\PythonProject4\.venv\Scripts\python.exe
```

### 打包为 EXE

不要直接只对 `正式版3.0.py` 执行默认 PyInstaller 命令。运行引擎通过
`importlib` 动态加载，默认分析会漏掉 `v3.legacy_engine`，启动自动化时会出现：

```text
ModuleNotFoundError: No module named 'v3.legacy_engine'
```

请双击：

```text
打包3.0.bat
```

该脚本使用 `QQ炫舞3.0.spec`，会显式收集整个 `v3` 包、Ultralytics
推理数据以及 `img`、`moxing`、`resres` 资源；同时排除本程序不用的
TensorFlow、Paddle、ONNX Runtime 等大型导出后端。完成后的目录是：

```text
dist/QQ炫舞3.0/
```

可编辑的自定义怪物模板会额外放在 EXE 同级目录：

```text
dist/QQ炫舞3.0/img/自定义/guai1.png
```

以后修改 Python 代码或增加模块后，重新运行 `打包3.0.bat`，不要继续使用旧 EXE。
打包脚本会自动执行不带界面和按键操作的模块/资源自检，结果保存在：

```text
dist/QQ炫舞3.0/打包自检结果.txt
```

两个 BAT 文件本身只包含 ASCII 命令，实际的中文文件名、资源复制和安全自检由
`tools/package_v3.py` 处理，避免 Windows CMD 因 UTF-8/GBK 编码不一致而把
`echo`、标签或中文路径拆成错误命令。

#### 无黑框单文件版

需要只复制一个 EXE 到其他电脑时，双击：

```text
3.0单文件打包.bat
```

脚本使用 `QQ炫舞3.0单文件.spec`，生成：

```text
dist/QQ炫舞3.0单文件.exe
```

该版本设置了 `console=False`，正常启动不会显示黑色控制台窗口，也不需要携带
`_internal` 目录。第一次启动会将运行依赖解压到 Windows 临时目录，因此启动
速度会比目录版慢；退出后临时运行文件由 PyInstaller 清理。

程序设置保存在 EXE 同级的 `v3_settings.json`。第一次打开自定义模板目录或启用
自定义模式时，程序会自动在 EXE 同级建立 `img/自定义`，并释放内置的
`guai*.png`；以后不会覆盖用户替换过的模板。

“仅替换怪物识别（保留原地图路线）”会继续执行地图下拉框对应的完整路线、
平台和爬绳逻辑，只把怪物坐标来源替换为 `img/自定义/guai*.png` 模板匹配。开启
自定义模板后不会加载或回退到YOLO；目录为空或图片无法读取时会直接停止并提示，
避免用户以为正在使用自定义模板，实际却由YOLO参与识别。
它与“启用自定义模式”互斥；后者使用用户记录的左右边界往返路线。

所有地图统一使用固定槽位取色补血、补蓝逻辑。怪物选择 YOLO、地图模板或
`img/自定义` 模板时，只替换怪物坐标来源，不改变药水判断。1366×768完整原图
确认HP内槽屏幕X约为504～607，MP内槽约为612～716；程序扣除客户区左偏移后，
按页面百分比分别在两条槽内取点。Y固定在客户区底部上方12px，槽内部约为屏幕
Y=787；客户区顶部为31、高度为768时，检测Y为
`31 + 768 - 12 = 787`，不会再落到Y=794的深色下边框，也不会
使用超出窗口的固定 `826`。取色点必须连续两帧为空白且距离上次按药至少 2 秒才会
再次按键，避免窗口位置不正确时连续消耗药水。

### 截图测试模式

测试模式现在用于开启实时截图预览，不再关闭自动化功能。勾选后仍会正常运行所选地图路线、移动、攻击、补血补蓝和完整轨迹日志；启动时还会自动还原游戏窗口，在保持游戏原分辨率不变的情况下把窗口固定到屏幕左上角，并读取实际客户区尺寸。蘑菇 V2 会按真实宽度扩展人物和怪物检测范围，例如 `1366x768` 下会覆盖最右侧额外的 86px。启动后先选择地图，再点击“启动（截图）”（也可以按 `F10`）。预览区域会实时显示：

- 绿色怪物识别框及当前怪物数量。
- 自身人物位置的屏幕坐标。
- 当前地图、检测方式、截图区域和实际检测 FPS。
- 人物搜索模式、人物灰度模板匹配耗时和怪物检测/YOLO 推理耗时。

截图画面直接复用正常怪物检测线程已经取得的图像和识别结果，不会另外启动第二套
YOLO，也不会因为页面预览而重复推理。预览转发最高约 `15 FPS`，用于控制界面绘制
和图像复制开销；测试模式下 YOLO 检测循环仍以 `60Hz` 为目标（约每 `16.67ms`
一轮）。如果截图、人物定位和 YOLO 推理总耗时超过 `16.67ms`，循环不会额外等待，
实际检测 FPS 会低于 60。未勾选测试模式时，正常自动化继续使用 `25Hz` 目标节奏。

所有地图在截图测试模式下仍使用正常自动化的人物定位和怪物识别流程。人物模板采用“一次选择、整次固定”：启动时最多检测 3 次 `dengpao.png`；只有灯泡相似度达到 `0.80`，本次运行才固定使用灯泡，否则固定使用 `xueliang.png`。模板固定后会缓存灰度图，首帧执行全区域匹配，后续优先搜索上一帧附近；连续两次局部失败后才执行一次全区域重定位。界面中的 `SELF` 标记和怪物框来自参与真实攻击判定的同一帧结果，因此预览与实际打怪逻辑保持一致。

推荐启动方法：在主页面“运行配置”的“运行模式”中勾选：

```text
测试模式（开启实时截图，其他功能正常）
```

勾选后页面会显示实时检测预览，“启动”按钮会变为“启动（截图）”。该选择会随
其他设置一起保存到 `v3_settings.json`，下次打开软件会自动恢复。取消勾选后只是
隐藏截图预览并恢复普通检测节奏，地图路线、移动和攻击在两种模式下都会执行。

### 纯识别测试模式

页面新增“纯识别测试（只截图识别，不执行任何动作）”。该模式用于人工检查怪物
模型或 `guai*.png` 模板是否正确命中、识别框位置和置信度是否合理。启动后只会：

- 保持游戏原分辨率并把窗口固定到屏幕左上角；
- 截取完整游戏窗口，包括底部血量、蓝量区域；
- 按当前地图和自定义模板设置识别怪物；
- 在预览中绘制怪物框、序号、置信度、人物位置和实际识别耗时；
- YOLO 以最高 `60Hz` 目标节奏运行，实际帧率取决于推理耗时。

纯识别测试不会运行地图路线，不会移动、攻击、追怪、爬绳、补血补蓝，也不会发送
任何游戏按键。它与“测试模式（开启实时截图，其他功能正常）”互斥，勾选其中一个
会自动取消另一个。

旧入口开关仍保留兼容。打开 `正式版3.0.py`，设置：

```python
TEST_MODE = True
```

也可以不改代码，使用命令行参数让页面首次默认勾选测试模式：

```powershell
python .\正式版3.0.py --test
```

启动脚本也会透传参数：

```powershell
.\启动3.0.bat --test
```

模板检测地图需要把 `guai1.png`、`guai2.png` 等图片放在对应的 `img/地图名/` 目录；YOLO 地图继续读取 `moxing/地图名.pt`。

全局热键保持为：

- `F10`：启动
- `F11`：停止
- `F12` 或 `Ctrl+Alt+Q`：备用停止

也可以直接使用界面中的“启动”和“停止”按钮。配置会自动保存到项目根目录的 `v3_settings.json`；打包为 exe 后，配置保存在 exe 同目录。

每次正式运行会在项目或程序同级的 `logs/` 目录生成一份
`运行轨迹_日期_时间.log`。文件采用一行一个 JSON 事件的格式，记录怪物检测、
人物匹配、攻击意图、实际攻击按键、移动切换和耗时；后台线程负责写入，不阻塞
YOLO 和路线线程。停止后日志路径会显示在运行日志中，可用于复盘不流畅的具体时段。

- 群体攻击、闪现、检测框开关。
- 红量、蓝量和绳子延迟配置项。
- F10/F11 全局启停、F12 与 `Ctrl+Alt+Q` 备用停止。

- 原有 `img`、`moxing`、`resres` 资源目录与模型命名方式。

## 性能与稳定性变化

- YOLO 模型按路径缓存。同一模型第二次启动不再重复加载。
- YOLO 只保留怪物类别并限制单帧最大候选数；检测循环按目标帧周期自适应补时，不再在推理耗时后固定追加等待。
- 每个检测线程复用一个 MSS 截图上下文，减少每帧创建与销毁对象的开销。
- 人物模板使用灰度缓存和上一帧附近优先搜索，连续两次局部失败后再执行全区域重定位。
- 页面可调整 YOLO 怪物置信度，范围 `0.30～0.95`、默认 `0.65`，正式运行与测试预览共用。
- 攻击意图带生成时间和有效期，通过条件变量即时唤醒攻击处理；公共地图仍保留 `0.45` 秒复检冷却。蘑菇 V2 不增加固定复检等待：先丢弃攻击完成前截到的陈旧画面；攻击后的600ms死亡动画窗口内，如果目标换边、数量增加或横向位置明显变化，立即判定为活怪并快速补刀，只有位置和数量基本不变的疑似死亡残影才继续最多3张新画面确认；超过窗口遇到的新怪立即正常攻击。
- 蘑菇V2会额外识别怪物头顶 `51×8` 血条中的绿色剩余血量。检测必须同时满足荧光绿色、白色斜面外框和黑色内框，远处绿树、草地与技能绿色不会仅凭颜色被当成血条。绿色长度可以从1px到满条变化；只要仍有绿色，就作为“怪物明确存活”的强证据，跳过死亡动画等待并继续攻击。血条会优先关联已经识别到的怪物，模板暂时漏掉怪物身体时再按动态学习的血条纵向偏移推断目标位置；空血条不会命中。
- 蘑菇V2会在人物附近使用用户提供的左右头部模板识别实际面向。攻击前若画面朝向与锁定目标相反，会先短促纠正方向再攻击；人物受击出现黑色闪烁或本帧置信度不足时，不覆盖上一次可靠方向，也不会对同一张旧截图反复转身。关键日志保留 `mushroom_v2_facing_corrected`、`mushroom_v2_facing_fallback` 和 `mushroom_v2_facing_reasserted`；正常朝向逐帧结果不再重复写入。
- 如果同一侧怪物持续存在、人物朝向画面又连续不可靠，蘑菇V2会在第三次攻击前重新轻点怪物所在方向，强制修正受击后背向造成的连续空打；该动作记录为 `mushroom_v2_facing_reasserted`，不会盲目把目标方向切到另一侧。
- 蘑菇V2单帧漏识别时保留上一帧追怪/战斗动作，连续两帧没有目标才恢复巡逻，避免每约140ms在移动、停下、攻击之间反复切换。
- 蘑菇V2增加同侧目标锁定：锁定侧仍有怪物时持续朝该侧攻击，即使另一侧出现更近目标也不回头；只有锁定侧数量归零且另一侧仍有目标时才切换朝向。检测线程的攻击方向只作为攻击许可，最终方向由最新两侧目标快照决定，避免消费旧方向后打空。
- 战斗结束到恢复路线之间使用260ms非阻塞移动防抖，覆盖约两张当前模板检测画面；期间检测与攻击继续全速运行，新目标重新出现时原地续打，持续没有怪物才按下巡逻方向键，减少两次攻击之间插入一步走路。
- 当前攻击距离外的近身补刀带扩展到80px；刚完成攻击后，目标只在补刀带外至340px之间时先观察150ms，怪物自行靠近便直接续打，仍在外侧才追怪，超过340px则立即追击。该距离滞回减少攻击边缘反复出现“追一步、停下、再攻击”。
- 蘑菇V2在严格攻击距离外增加60px近身补刀带：怪物受击后轻微后退时人物保持原地，根据怪物在左侧或右侧转身继续攻击，不会在两次攻击之间插入一步追怪移动；真正超过近身带后才开始追怪。
- 攻击后的路线移动锁定 `0.75` 秒，战斗结束需要连续三帧确认并满足时间宽限，避免识别间隙插入一步巡逻移动。
- `pydirectinput` 调用间隔缩短为 `0.01` 秒，公共攻击动作使用更短且可中断的方向稳定时间。
- 模板地图先在下半区定位人物，再把怪物模板匹配缩小到人物左右“攻击范围 + 额外追怪200px + 20px余量”和纵向“攻击高度 + 20px余量”；自定义怪物模板最大尺寸仍被完整覆盖，常用搜索区由约 `840×200` 缩小到 `800×180`。人物偶发一帧定位低分时，只用上一可靠位置裁剪模板搜索区，不使用旧坐标发起攻击，避免退回 `1382×330` 全区域扫描造成帧率下降。
- 模板地图的攻击范围使用矩形判定：横向距离 `dx < 界面攻击距离`，同时纵向距离 `dy < 70`。界面填写 `300` 即表示 `dx < 300`，不是圆形半径或直线距离。
- 模板诊断会输出每个 `guai*.png` 命中的真实置信度，并每秒汇总截图、怪物模板匹配、人物匹配与整帧处理耗时以及估算 FPS，便于区分误识别和性能瓶颈。
- 蘑菇 V2 保留左右两个绳脚入口，二者高度均为 `Y≈147`：`X=28～30` 执行“向右 + C + 上”，`X=32～34` 执行“向左 + C + 上”；`X=31` 只用于过渡，不直接起跳。失败重试会重新选择当前可到达的一侧。实际绳顶稳定坐标为 `Y=117`，到达后立即向右离绳并进入上层平台，不会修改蘑菇地图1及其他地图路线。
- 蘑菇V2每连续刷图20分钟，会把“绳中休息”标记到下一次爬绳：人物到达绳子中段 `Y≈132` 后释放移动、跳跃和攻击键，休息60秒，再继续向上爬到 `Y=117` 并恢复原来的上层刷图路线。休息可被F11立即中断；若休息时被怪打落，会保留剩余休息时间，重新爬到中段后继续休息。
- 结构化日志改为关键事件模式：保留怪物检测状态变化及周期性能摘要、攻击按键、方向纠偏、移动开始/停止、补药、爬绳结果和异常；小地图逐帧、动作决策/应用、攻击意图内部流转、重复战斗阶段及普通朝向帧不再写入。人物轨迹约每2秒保留一条，并在爬绳等关键阶段变化时额外记录。
- 爬绳挂绳观察窗口由 `0.90s` 缩短为 `0.72s`，绳顶向右离绳按键由 `0.25s` 调整为 `0.35s`；日志样本中左右入口都能到达 `Y=117`，延长离绳按键可减少因只移动1px而产生的第二次离绳重试。
- 蘑菇V2绳区优先级为“近怪战斗/追怪 > 爬绳”：到达绳脚但检测到怪物时先原地转向攻击或追怪，连续确认没有目标后才开始跳绳，避免攻击和跳绳同时抢方向键、C键和上键。
- 新增“蘑菇V3”录制路线模式。页面可直接以30Hz记录小地图黄色人物坐标：左右键形成平台线，C键形成一次性跳跃点，上/下键形成平台之间的绳子连接。走完一整圈后按F7保存为 `v3/map/recordings/蘑菇V3路线.json`，同时生成彩色 `蘑菇V3路线.png` 预览图。V3按有序坐标循环回放，避免去程、回程或交叉路线在同一坐标选错动作；偏离当前路线过远时才执行全路线重定位。
- 蘑菇V3固定使用 `img/自定义/guai*.png` 模板，不加载YOLO；战斗复用V2的人物定位、面向纠正、同侧目标锁定、绿色血条和死亡动画抑制。动作优先级为“近怪战斗/追怪 > 战斗消失确认 > 继续录制路线”。详细操作见 `蘑菇V3路线录制说明.md`。
- 地图路线、左上角人物定位和怪物检测分别运行在独立线程；同一个怪物检测线程内的多张 `guai*.png` 仍按顺序匹配，以避免盲目增加线程造成 CPU 与内存带宽争抢。
- 模板检测线程增加停止条件，F11 后不再遗留无法退出的检测循环。
- 修复“武陵海盗船2”指向不存在的 YOLO 模型的问题，改用项目中已有的怪物模板检测。
- 日志通过 Qt 信号跨线程写入，避免工作线程直接操作界面控件。
- 自动化任务只允许单实例运行，阻止连续按 F10 创建重复线程。
- 网络检查不再在模块导入阶段执行，断网不会卡住界面启动。
- 配置使用临时文件加原子替换保存，降低异常退出时损坏 JSON 的概率。

## 3.0 公共逻辑抽取

兼容引擎已进一步从约 7580 行缩减到约 5560 行，减少约 26%。地图专属路线没有合并，
但以下跨地图重复行为已经统一成公共方法：

- `已请求停止()`：统一检查线程停止标记和 `stop_event`。
- `可中断等待()`：长等待期间每 50ms 检查停止信号。
- `读取人物位置()`：统一处理人物坐标的线程锁。
- `释放水平移动键()`：统一释放左右方向键。
- `释放攻击键()`：统一释放用户配置的攻击键。
- `轻点方向()`：统一攻击前的朝向校正。
- `等待战斗恢复()`：替换旧版无休眠忙循环，避免暂停期间占满 CPU。
- `处理战斗暂停()`：替代 16 张地图中完全相同的约 70 行攻击代码。
- `load_monster_templates()`：按实际文件加载全部模板，不再漏掉最后一张图。
- `person_locator.py`：普通自动化与测试模式共用人物定位；灯泡/血量只在启动时选择一次，统一使用 `0.80` 阈值。

检测循环还做了以下简化：

- 删除两个只执行一次的 `while True` 决策循环，改成直接的 `if/elif`。
- 全文件的 `while True` 数量从 117 处降低到约 80 处；保留下来的主要是地图路线循环。
- 同一截图不再重复转换为 BGR。
- HSV 阈值数组改成模块级常量，不再每帧重新创建。
- 只有开启“显示检测框”时才执行矩形和文字绘制。
- 模板去重判断改用 `any()`，删除重复计数器和未使用变量。
- 删除兼容引擎内已废弃的旧 UI、旧热键线程和旧启动入口；界面职责只保留在 `v3/main_window.py`。
- 解轮识别改为数据驱动的四区域循环，失败重试增加日志、休眠和停止检查。
- 验证截图复用同一份 JPEG 字节，不再保存后重新从磁盘读取。

机械抽取脚本保存在 `tools/refactor_legacy_engine.py`。以后从旧版本重新同步地图
代码时，可以用它再次完成相同的公共逻辑替换。

## 如何增加地图

如果新地图仍使用现有动作风格：

1. 在 `v3/map/routes.py` 中增加地图动作函数。
2. 把模型放进 `moxing/`，模板资源放进对应资源目录。
3. 在 `v3/map/definitions.py` 的 `MAP_SPECS` 中增加一行：

```python
MapSpec("新地图显示名称", "新地图动作函数", detector="yolo")
```

模板检测地图把 `detector` 改为 `"template"`。界面下拉框和任务分发会自动出现，不需要再添加成片的 `if map_choice == ...`。

“蘑菇半图上层备用”复用 `蘑菇地图1半图上` 路线，怪物模板放在：

```text
img/蘑菇半图上层备用/guai1.png
img/蘑菇半图上层备用/guai2.png
img/蘑菇半图上层备用/guai3.png
...
```

程序会自动读取该目录下全部 `guai*.png`。

该备用地图只把怪物识别改为 `guai*.png`，人物定位与 1.9 的 YOLO 战斗链路保持一致：启动时固定选择 `dengpao.png` 或 `xueliang.png`；血量模板使用 `ccy - 40`，灯泡模板使用 `ccy + 70` 作为攻击参考高度。战斗屏幕坐标只在检测线程内部使用，不会覆盖左上角小地图的 `renwu_pos`。

## 如何增加配置或界面功能

1. 在 `v3/config.py` 的 `AppConfig` 添加字段和校验。
2. 在 `v3/main_window.py` 添加控件，并在 `collect_config` / `apply_config` 中绑定。
3. 在 `v3/automation_service.py` 的 `_configure_engine` 把配置传给运行引擎。

界面、配置和业务调度互相独立，因此修改主题不会碰地图算法，增加地图也不需要修改界面代码。

主窗口默认及最小尺寸为 `1182 × 937`，用于完整显示全部配置项和日志区域。
